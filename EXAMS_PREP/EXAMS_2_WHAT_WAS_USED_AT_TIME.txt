The possibility to find which software the user was using at that time of Captured whic is one of the main goals of memory forensics using tools 
like Volatility 3 and Volatility 2.
From a RAM image, we can often determine:
| Investigation Goal              | Volatility 3 Command                                   | Volatility 2 Command             | Short Explanation                                                           |
| ------------------------------- | ------------------------------------------------------ | -------------------------------- | --------------------------------------------------------------------------- |
| Which applications were running |  windows.pslist  /  windows.pstree                     |  pslist  /  pstree               | Shows active processes like  chrome.exe,   winword.exe,   powershell.exe .  |
| What documents were open        |  windows.handles                                       |  handles                         | Reveals files opened by applications such as  .docx,   .pdf,   .xlsx .      |
| Browser activity                |  windows.pslist,   windows.netscan,   windows.dlllist  |  pslist,   netscan,   dlllist    | Identifies browsers, visited sessions, and active web connections.          |
| Chat sessions                   |  windows.pslist,   windows.handles                     |  pslist,   handles               | Detects chat apps like  Skype,   Teams,   Discord,  or open chat databases. |
| Command history                 |  windows.cmdline,   windows.consoles                   |  cmdline,   consoles             | Recovers executed commands and console history from CMD/PowerShell.         |
| Malware execution               |  windows.malfind                                       |  malfind                         | Detects injected code, shellcode, and suspicious memory regions.            |
| USB devices                     |  windows.registry.printkey                             |  printkey                        | Extracts USB insertion history from Windows Registry.                       |
| Network connections             |  windows.netstat,   windows.netscan                    |  connscan,   netscan             | Shows active/recent network sessions and remote IP addresses.               |
| Decrypted data in memory        |  windows.memmap,   windows.dumpfiles                   |  memdump,   procdump             | Dumps process memory where decrypted content may exist temporarily.         |
| Clipboard contents              |  windows.clipboard  *(if supported)*                   |  clipboard  *(plugin-dependent)* | Recovers copied text/data from the Windows clipboard.                       |
| Passwords/tokens (sometimes)    |  windows.lsadump,   windows.hashdump                   |  lsadump,   hashdump             | Extracts password hashes, credentials, and authentication tokens.           |
 

1. Find Running Software /  Which applications were running
The first step is usually the pslist which shows the active processes:
#Volatility 3
python3 vol.py -f AdamFTriage.mem windows.pslist

#Volatility 2
python2 vol.py --profile=Win7SP1x64 -f AdamFTriage.mem pslist

This shows active processes such as:
| Process        | Meaning               |
| -------------- | --------------------- |
| chrome.exe     | Google Chrome open    |
| firefox.exe    | Firefox running       |
| outlook.exe    | Email client          |
| winword.exe    | Microsoft Word        |
| putty.exe      | SSH session           |
| cmd.exe        | Command prompt        |
| powershell.exe | PowerShell            |
| wireshark.exe  | Packet capture        |
| malware.exe    | Suspicious executable |

3. Browser Activity: Identifies browsers, visited sessions, and active web connections. 
You can identify browsers from processes:
| Browser Process | Browser           |
| --------------- | ----------------- |
| chrome.exe      | Google Chrome     |
| firefox.exe     | Mozilla Firefox   |
| iexplore.exe    | Internet Explorer |

Then investigate:
- history files
- cache
- network sockets
- URLs in memory

Useful plugins:
- netscan
- dlllist
- handles
- yarascan

5. GUI Applications Running at Capture Time
Memory images are especially powerful because they capture:
- LIVE applications
- unsaved data
- active sessions

You may recover:
chat messages
- unsaved Notepad text
- passwords in memory
- clipboard contents

4. Find Hidden or Injected Malware
Very important forensic step:
#Volatility 3
windows.malfind

#Volatility 2:
malfind

This detects:
- injected code
- reflective DLL injection
- shellcode
- process hollowing

5. Command History
You can recover terminal activity with CMD history

#Volatility 3
windows.cmdline or windows.consoles

This may reveal:
- ipconfig
- net user
- ping
- whoami
- passwords
- malware commands

6. Network Connections
This reveals internet/software activity.
#Volatility 3
windows.netstat or windows.netscan
This may show:
- remote IPs
- malware C2 servers
- web sessions
- VPN activity
- RDP sessions

windows.pslist

#Step 2 — Tree relationships
windows.pstree

windows.netscan

#Step 4 — Malicious injections
windows.malfind

#Step 5 — Command history
windows.consoles

#Step 6 — Loaded DLLs
windows.dlllist

11. Example of What You Might Discover
Example forensic findings:
- chrome.exe       -> browsing activity
- outlook.exe      -> email usage
- putty.exe        -> SSH connections
- cmd.exe          -> command execution
- truecrypt.exe    -> encrypted volumes
- wireshark.exe    -> packet captures
- powershell.exe   -> scripts executed

12. Very Important Reality
RAM only shows:
what existed during capture time not entire historical usage
If the program was closed long ago memory overwritten then evidence may disappear.

But memory is extremely valuable because it preserves:
- live state
- decrypted information
- volatile evidence
