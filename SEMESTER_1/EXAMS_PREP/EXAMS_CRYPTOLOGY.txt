CRYPTOLOGY 
is the overarching science of secure communications, sitting at the intersection of mathematics, 
computer science, and engineering. It acts as an ongoing "cat-and-mouse" game between constructing 
secure codes and attempting to break them.

Hash is not encrypting or encryption

The field is broadly divided into two primary disciplines: 
- Cryptography: The art and science of creating secure systems to hide the meaning of data. 
    It translates readable plaintext into unreadable ciphertext using an encryption key.
- Cryptanalysis: The science and study of analyzing, attacking, and breaking these codes 
    to recover the original information without knowing the secret key.

Core Concepts:
- Encryption & Decryption: Encryption scrambles data; decryption uses a secret key to return it to a readable format. 
- Symmetric vs. Asymmetric: Symmetric ciphers use the same key for both parties, 
    while asymmetric (or public-key) cryptography uses a paired public/private key system.
- Hashing & Digital Signatures: Techniques used to verify data integrity 
    (confirming the data hasn't been altered) and authenticate the identity of the sender.

A cipher: Encryption comes from cipher
is an algorithm or a precise set of steps used to perform encryption and decryption. 
It acts as the mechanical "recipe" that transforms readable information (plaintext) into a scrambled, 
unreadable format (ciphertext), and vice versa.

How Ciphers Use Keys
An encryption algorithm is typically public knowledge; 
its security relies entirely on keeping the key a secret (a concept known as Kerckhoffs's Principle).
- Symmetric Ciphers: The sender and receiver use the same secret key to lock and unlock the data (e.g., AES). 
    It is incredibly fast but requires a secure way to share the key first.
- Asymmetric Ciphers: Uses a mathematically linked key pair. A Public Key encrypts the data, 
    but only the corresponding private, matching Private Key can decrypt it (e.g., RSA).

- Encoding/Encryption: Encoding takes readable information (like text, images, or audio) and converts it into a specific, 
standardized format

- Decoding/Decryption: Decoding is the exact reverse of encoding. It takes the standardized, encoded format and converts 
it back into its original form.

Why It Matters
Today, cryptology underpins almost all digital security. 
It is essential for protecting e-commerce transactions, securing messaging apps, 
maintaining privacy in computer networks, and managing digital signatures

CRYPTOGRAHY
Cryptographic protocols operate across different layers of the OSI model to provide three core pillars 
of information security: Integrity (ensuring data is unaltered), Authentication (verifying identities), 
and Confidentiality (keeping data secret).
Below is a detailed breakdown of these cryptographic primitives, followed by how they map to specific 
protocols across the OSI model layers.

Part 1: Core Cryptographic Primitives 
1. Integrity (Hashing), there is no way you could protect if only send integrity unless you add confidentiality
Integrity algorithms verify that data has not been modified, corrupted, or tampered with during transit. 
They take an input of any size and produce a fixed-size string (a hash value or checksum). 
This process is strictly a one-way function; you cannot reverse-engineer the original data from the hash value. 
- MD5 (Message Digest 5): Generates a 128-bit hash value. MD5 is cryptographically broken and suffers from severe 
    collision vulnerabilities (where two different inputs produce the identical hash). 
    It is no longer safe for security purposes, though it is still occasionally used for basic, 
    non-secure file integrity checks.
    The MD5 is just a standard mathematical checksum without a secret key, anyone can generate a valid MD5 hash for any piece of text
- SHA (Secure Hash Algorithm): A family of cryptographic hash functions designed by the NSA.
- SHA-1: Generates a 160-bit hash. Like MD5, SHA-1 is considered insecure against well-funded attackers due 
    to collision vulnerabilities.
   = SHA-2: Includes variants like SHA-256 and SHA-512. It is currently the industry standard for securing websites, 
        software distribution, and blockchain technologies.
   = SHA-3: The latest family member, based on a completely different internal design (the Keccak permutation), 
        used as a highly secure alternative to SHA-2.

📤 The Sender
   1. Message: Has the raw message ready to send.
   2. Hash(Key + Message): Combines the message and runs them together through a hashing algorithm (like SHA-256/MD5).
   3. Send: Transmits the unencrypted raw message paired directly with the Hash, like SHA-256/MD5.

📥 The Receiver
   1. Receive: Gets the raw message and the attached fingerprint over the network.
   2. Read and Separate: Reads the plaintext message normally, but slides the received fingerprint to the side.
   3. Take Message + Hash: Takes that plaintext message and runs it through the exact same hashing algorithm using the exact same secret key.
   4. Compare: Compares the newly calculated fingerprint with the one sent by the sender. If they are a 100% exact match, 
    the identity of the sender and the integrity of the data are officially verified.

2. Authentication (Verifying Identity)
Authentication ensures that the sender of a message is truly who they claim to be, preventing impersonation and tampering.
- HMAC-MD5 / HMAC-SHA-1 (Hash-based Message Authentication Codes): These combine a traditional cryptographic hash function
    (MD5 or SHA-1) with a secret cryptographic key. Because a secret key is involved, an attacker cannot modify the message 
    and simply recalculate the hash; they would need the secret key to generate a valid HMAC. This guarantees both integrity 
    and data origin authentication.
- RSA (Rivest–Shamir–Adleman): An asymmetric (public-key) algorithm used for digital signatures and identity verification. 
    The sender signs a message hash using their private key, and anyone can verify the signature using the sender's widely 
    distributed public key. This provides non-repudiation (the sender cannot deny sending the message). 
- DSA (Digital Signature Algorithm): Another asymmetric algorithm designed strictly for digital signatures, 
    based on the algebraic properties of modular exponentiation and the discrete logarithm problem. Like RSA, 
    it provides authentication and non-repudiation, but it cannot be used for data encryption.

repudiation: In digital environments, repudiation is the denial of an action
    For example, a user executing a transaction or sending a message and later denying they did so. 
    To prevent this, cryptographic systems use non-repudiation—a mechanism (like a digital signature) 
    that provides undeniable proof of the origin, identity, and integrity of a message or transaction

📤 The Sender
   1. Message: Has the raw message ready to send.
   2. Hash(Key + Message): Combines the secret key with the message and runs them together through a hashing algorithm (like SHA-256).
   3. Authenticated the message: This calculation generates the unique HMAC fingerprint (also called an Authentication Tag or MAC).
   4. Send: Transmits the unencrypted raw message paired directly with the HMAC fingerprint.
📥 The Receiver
   1. Receive: Gets the raw message and the attached HMAC fingerprint over the network.
   2. Read and Separate: Reads the plaintext message normally, but slides the received HMAC fingerprint to the side.
   3. Take Message + Hash(Key): Takes that plaintext message and runs it through the exact same hashing algorithm using the exact same secret key.
   4. Compare: Compares the newly calculated fingerprint with the one sent by the sender. If they are a 100% exact match, the identity of the sender 
    and the integrity of the data are officially verified.

3. Confidentiality (Encryption)
Confidentiality algorithms scramble data using encryption algorithms so that unauthorized parties cannot read it. 
These are symmetric algorithms, meaning the exact same secret key is used to lock (encrypt) and unlock (decrypt) the data.
- DES (Data Encryption Standard): An older symmetric block cipher that uses a 56-bit key. Because of its short key length, 
    DES is completely obsolete and can be cracked in less than a day by modern computers using brute-force attacks.
- 3DES (Triple DES): An intermediate fix designed to extend the life of DES. It runs the DES algorithm three 
    times consecutively over each data block using two or three different keys (effectively providing a 112-bit or 
    168-bit key strength). While more secure than DES, 3DES is computationally slow and has been phased out.
- AES (Advanced Encryption Standard): The global gold standard for symmetric encryption. It operates on 128-bit blocks 
    of data and supports key lengths of 128, 192, and 256 bits. AES is highly efficient in both hardware and software, 
    and there are no known practical attacks against it when properly implemented.

A username/password by itself is not encryption. It is an authentication method that proves the user's identity.

The actual VPN encryption is usually handled separately, most commonly using:
- Asymmetric cryptography (certificates and public/private keys) to establish a secure connection and verify the identities of the client and server.
- Diffie-Hellman (DH) key exchange to securely generate and exchange a shared secret key over an insecure network without transmitting the key itself.
- Symmetric cryptography (such as AES) to encrypt and decrypt the VPN traffic after the connection is established.

Therefore, a username/password login does not automatically mean symmetric or asymmetric encryption.

Certificate-based OpenVPN (most common):
- The server has a digital certificate and private key.
- Clients verify the server's certificate to ensure they are connecting to a trusted server.
- Clients may also have their own certificates for mutual authentication.
- Username/password credentials may be used as an additional authentication factor.

This setup uses asymmetric cryptography for authentication, Diffie-Hellman for secure key exchange, and symmetric encryption (AES, etc.) for protecting the VPN tunnel.
OpenVPN uses username/passwords to authenticate users and verify their identity before access is granted. It then uses asymmetric cryptography (digital certificates and 
    public/private keys) to establish trust between the client and server. During the connection process, Diffie-Hellman is used to securely create a shared secret key. 
    Once the connection is established, OpenVPN uses symmetric encryption, typically AES, to efficiently encrypt and decrypt all data transmitted through the VPN tunnel.

Diffie-Hellman (DH) is a key exchange algorithm used in cybersecurity to allow two parties to securely create a shared secret key over an insecure network.
The shared secret is then used as a symmetric encryption key (such as AES) to encrypt communications, without ever transmitting the key itself across the network.
In VPNs like OpenVPN, Diffie-Hellman helps the client and server securely agree on encryption keys before the VPN tunnel is established.
It provides secure key exchange and supports Perfect Forward Secrecy (PFS) when using ephemeral keys, meaning past communications remain secure even if a 
    long-term key is later compromised.

The Affine Cipher is a classical symmetric encryption algorithm used to encrypt messages directly using a mathematical substitution formula. Diffie-Hellman is a modern 
    key exchange algorithm that does not encrypt data itself but allows two parties to securely generate a shared secret key, which can then be used by encryption algorithms 
    such as AES.

1. Symmetric Encryption
Symmetric encryption is a method of protecting data where the same secret key is used for both encryption and decryption.

How it works:
1. Alice and Bob agree on a secret key.
2. Alice encrypts the message using the secret key.
3. The encrypted message (ciphertext) is sent to Bob.
4. Bob uses the same secret key to decrypt the ciphertext back into the original message.

Example:-->
Plaintext:      HELLO
Secret Key:     K123
Encrypt --> Ciphertext: X7P9Q
Decrypt using K123 --> HELLO

Characteristics:
- Uses one shared key.
- Very fast and efficient.
- Suitable for encrypting large amounts of data.
- The biggest challenge is securely sharing the secret key.

Common Symmetric Algorithms:
- DES (obsolete)
- 3DES (deprecated)
- AES (current standard)

Real-World Use
After an OpenVPN connection is established, AES is typically used to encrypt all VPN traffic because it is fast and secure.

2. Asymmetric Encryption
Asymmetric encryption uses two different keys:
- Public Key – shared openly.
- Private Key – kept secret.

The keys are mathematically related. How it works:
1. Bob creates a public key and a private key.
2. Bob shares his public key with everyone.
3. Alice encrypts a message using Bob's public key.
4. Bob decrypts the message using his private key.

Example:
Bob's Public Key  --> Shared publicly
Bob's Private Key --> Secret

Alice encrypts with Public Key
           ↓
Encrypted Message
           ↓
Bob decrypts with Private Key

Characteristics:
- Uses two keys instead of one.
- More secure for exchanging information over untrusted networks.
- Slower than symmetric encryption.
- Solves the key-distribution problem.

Common Asymmetric Algorithms
- RSA
- ECC
- Diffie-Hellman (used for key exchange rather than direct encryption)

Real-World Use
In OpenVPN:
- Certificates use asymmetric cryptography to establish trust.
- Diffie-Hellman securely exchanges key material.
- AES then encrypts the actual VPN data.

Comparison
| Feature          | Symmetric Encryption | Asymmetric Encryption               |
| ---------------- | -------------------- | ----------------------------------- |
| Number of keys   | One shared key       | Public key + Private key            |
| Speed            | Fast                 | Slower                              |
| Main purpose     | Encrypt data         | Authentication, trust, key exchange |

Simple Memory Trick, Think of it like a safe:

Symmetric Encryption:
- One key locks the safe.
- The same key unlocks the safe.

Asymmetric Encryption
- One key locks the safe (public key).
- A different key unlocks the safe (private key).

That's why modern systems such as OpenVPN, HTTPS, and SSH typically use both:
1. Asymmetric cryptography to establish trust and exchange keys.
2. Symmetric cryptography (AES) to encrypt the actual data efficiently.

Part 2: Mapping Cryptography to the OSI Model Layers
Security protocols integrate these cryptographic building blocks at different stages of network communication.
| OSI Layer | Layer Name   | Primary Security Protocols Involved    | Cryptographic Primitives Used                                                     |
|-----------|--------------|----------------------------------------|-----------------------------------------------------------------------------------|
| Layer 7   | Application  | HTTPS, SSH, S/MIME, PGP, DNSSEC        | RSA, DSA (for handshake); AES (for payload); SHA-256 (for integrity)              |
| Layer 6   | Presentation | TLS / SSL (Acts as a sub-layer here)   | RSA, ECDSA (Authentication); AES, 3DES (Confidentiality); HMAC-SHA (Integrity)    |
| Layer 5   | Session      | RPCSEC_GSS, SOCKS5                     | Typically passes cryptographic tokens or wraps lower-layer encryption sessions    |
| Layer 4   | Transport    | SSL / TLS, DTLS                        | Handshake negotiates RSA/DH; Data transfer uses AES and HMAC-SHA                  |
| Layer 3   | Network      | IPsec (AH and ESP)                     | ESP uses AES/3DES for privacy; AH/ESP use HMAC-SHA for integrity/auth             |
| Layer 2   | Data Link    | MACsec (802.1AE), WPA3 (Wi-Fi)         | AES-GCM (provides both confidentiality and integrity at the hardware frame level) |
| Layer 1   | Physical     | Bulk Optical Encryption, DWDM Security | Hardware-level AES encryption of the raw electrical or light bitstream            |

Detailed Layer Breakdown: 
- Layer 7 (Application Layer): Protocols like SSH (secure command-line access) or S/MIME / PGP (email encryption) operate here. For example, 
    PGP uses asymmetric keys (like RSA) to authenticate the sender and exchange a session key, then uses symmetric encryption (like AES) to keep the email 
    contents private.
- Layer 6 & 4 (Presentation / Transport Layers): TLS (Transport Layer Security) bridges these layers. When you connect to an https:// website, TLS performs a handshake.
    It uses RSA or elliptic curves to verify the website's identity (Authentication), exchanges a secret key, and then switches to AES to encrypt all web traffic 
    (Confidentiality) and HMAC-SHA to ensure packets aren't altered (Integrity).
- Layer 3 (Network Layer): IPsec (Internet Protocol Security) secures traffic at the packet level, commonly used to build Virtual Private Networks (VPNs). 
    It features two main headers:
- Authentication Header (AH): Uses HMAC-SHA to guarantee packet integrity and authenticate the sender, but does not encrypt the data.
   = Encapsulating Security Payload (ESP): Uses AES or 3DES to encrypt the payload (Confidentiality) while optionally using HMACs for integrity.
- Layer 2 (Data Link Layer): Protocols like MACsec (802.1AE) encrypt point-to-point physical links between switches, while WPA3 protects wireless local networks. 
    These rely heavily on AES running directly on network interface hardware to encrypt Ethernet frames or wireless signals instantly without slowing down the network.
 
RESUME
- Integrity (Hashing): Verifies the whole message has not been compromised by generating and comparing a digital fingerprint (the Hash).
- Authentication (Verifying Identity): Confirms the exact origin of the message by using a cryptographic Key (like an HMAC or Digital Signature).
- Confidentiality (Encryption): Codes the whole message into an unreadable, garbage-looking language (Ciphertext) that only authorized key-holders can read.

The Ultimate Quick-Check Checklist
When working on network or programming architecture, you can always test your tools against this cheat sheet:
   1. If you are ONLY using a standard Hash (like MD5 or SHA-256):
   - You have Integrity.
      - You do not have Authentication or Confidentiality.
   2. If you are using a Keyed Hash or Certificate (like HMAC or RSA):
   - You have Authentication and Integrity.
      - You do not have Confidentiality.
   3. If you are using a Tunnel/Symmetric Cipher (like OpenVPN with AES):
   - You have Confidentiality, Authentication, and Integrity.
   

To understand where these concepts fall, we look at the two protocols discussed in your scenario: 
MD5 (used in your first configuration scenario) and OpenVPN (used in your second scenario).
Here is exactly how they map to the security pillars:
1. MD5 (The Single Primitive)
MD5 is not a full security protocol; it is a single cryptographic algorithm (a hash function). Because it is just a hash, it only handles one pillar.
- Integrity (Yes): This is the only thing MD5 does in your configuration file example. It takes the text, creates a digital fingerprint, 
    and lets the server verify that the text wasn't accidentally corrupted during transit.
- Authentication (No): MD5 by itself cannot prove who sent the file. As shown in the scenario with Eve, anyone can write a fake file and calculate a 
    valid MD5 hash for it.
- Confidentiality (No): MD5 does not encrypt anything. Your port settings (8081 and 3333) remained completely readable in plaintext.

2. OpenVPN (The Complete Protocol Suite)
OpenVPN is a comprehensive security protocol suite. It does not rely on just one algorithm; it combines several different cryptographic 
    primitives to achieve all three pillars at the same time.
- Authentication (Handshake Phase): OpenVPN handles this in two ways during its startup phase. First, it uses asymmetric cryptography 
    (RSA or DSA) via TLS certificates to prove the server is legitimate. Second, it takes your Username/Password to prove your identity to the server. 
- Confidentiality (Data Phase): It achieves this using the AES-128-CBC symmetric cipher. 
    Once you are authenticated, all of your raw data packets are encrypted into unreadable ciphertext so hackers like Eve cannot read your traffic.
- Integrity (Data Phase): OpenVPN combines AES with a keyed hash called an HMAC (usually HMAC-SHA-256). This ensures that if Eve tries to 
    alter even a single bit of your encrypted data mid-transit, the server will detect the tampering and drop the packet.
