**Corrected DNS resolution flow for `testweb.com` (no caches at any level)**

1. **Browser / Application**  
   Checks its own DNS cache → miss

2. **Operating System**  
   Checks its DNS cache → miss  
   Checks the hosts file → miss

3. **Client → Recursive Resolver**  
   Client sends the query for `testweb.com` (A/AAAA) to the configured recursive resolver (ISP DNS or public resolver such as 8.8.8.8 / 9.9.9.9 / etc.)

4. **Recursive Resolver → Root server (`.`)**  
   Recursive resolver queries a root server  
   Root server replies with a referral to the `.com` TLD name servers

5. **Recursive Resolver → TLD server (`.com`)**  
   Recursive resolver queries a `.com` TLD server  
   TLD server replies with a referral to the authoritative name servers for `testweb.com`

6. **Recursive Resolver → Authoritative server**  
   Recursive resolver queries one of the authoritative name servers for `testweb.com`  
   Authoritative server replies with the IP address (A/AAAA record) of `testweb.com`

7. **Recursive Resolver → Client**  
   Recursive resolver returns the IP address to the client

8. **Client → `testweb.com` web server** (after DNS is finished)  
   Client opens a TCP connection to the obtained IP and receives the HTTP/HTTPS response from the web server

**Notes**
- Steps 1–7 are pure DNS.  
- Step 8 is the subsequent connection to the website (not part of the DNS process).  
- In real life the recursive resolver almost always performs steps 4–6 iteratively; the client only talks to the recursive resolver.
